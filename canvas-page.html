👨‍💻 Code-Together 15: Binary Search Trees

🎯 Overview

An in-class code-together activity implementing a Binary Search Tree (BST) from scratch using recursive patterns. Students implement BinarySearchTree.cpp guided by the instructor, building insert, search, three traversals (in-order, pre-order, post-order), and height. The activity covers the BST property, why in-order traversal produces sorted output, and introduces functors as a flexible alternative to hardcoded print traversals.

📖 Learning Objectives

By completing this activity, you will be able to:

  • Implement insert recursively, understanding that new nodes always become leaves and duplicates are ignored
  • Implement search and explain why it is identical to binary search on a sorted array, achieving O(log n) on a balanced tree
  • Implement in-order traversal and explain why it produces sorted output given the BST property
  • Implement pre-order and post-order traversals and identify a real use case for each
  • Implement height recursively, using -1 as the base case for nullptr so a leaf has height 0
  • Explain the public/private helper pattern: public methods provide a clean interface while private helpers recurse through the tree

📚 Teaching Order

Work through the files in order:

1. BinarySearchTree.h — Node struct and class declaration

Walk through the header. Discuss the BST property, the Node struct, and the public/private helper pattern (public wrappers call private recursive helpers).

Section What You’ll Learn
struct Node Each node holds data + two child pointers; nodes are heap-allocated
BST Property Left subtree < node < right subtree; holds recursively at every node
Public/Private Pattern Public insert(int) calls private insert_(Node*, int); hides tree internals

2. BinarySearchTree.cpp — Implementations (6 TODOs)

Section What You’ll Learn
TODO 1: insert_() BST property routes each value left or right; new nodes land as leaves; return-the-node pattern reattaches child pointers
TODO 2: search_() Same logic as binary search; each comparison eliminates one subtree; O(log n) balanced, O(n) degenerate
TODO 3: inorder_() Left → Root → Right; produces sorted output by BST property
TODO 4: preorder_() Root → Left → Right; root printed first; useful for cloning/serializing
TODO 5: postorder_() Left → Right → Root; children before parent; same order as safe deletion
TODO 6: height_() Base case: nullptr returns -1; each node adds 1 + max(left, right); height determines O(log n) vs O(n)

3. main.cpp — Demo driver (provided)

Section What You’ll Learn
Section 1: Build and visualize Insert 50, 30, 70, 20, 40, 60, 80; print all three traversals and height
Section 2: Search Search for values that exist and values that don’t; confirm correct true/false

🔧 Troubleshooting

CMake does not configure automatically

  1. Make sure you have Desktop development with C++ workload installed in Visual Studio
  2. Go to Project → CMake Settings and ensure the configuration is correct
  3. Try Project → Delete Cache and Reconfigure
  4. Verify that CMakeLists.txt is in the root of your cloned repository

Tests fail to build

  • Google Test is fetched automatically via CMake’s FetchContent — make sure you have an internet connection during the first build
  • Do not modify header files in the include/ folder

Running the Program

  1. In Visual Studio, select ct15-binary-search-trees.exe as the startup item from the dropdown
  2. Press Ctrl+F5 to run without debugging
  3. You should see output from each section as you complete the TODOs
Tip: Look for the // ! DISCUSSION: comments in each file — these explain the “why” behind each concept. The // ? SEE DIAGRAM: comments point you to visual aids in the images/ folder.
