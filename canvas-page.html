👨‍💻 Code-Together 15: Binary Search Trees - Day 1

🎯 Overview

An in-class code-together activity implementing a Binary Search Tree (BST) from scratch using recursive patterns. Students implement BinarySearchTree.cpp guided by the instructor, building insert, search, three traversals (in-order, pre-order, post-order), and height. The activity closes with a functor demo: three pre-built functor structs (PrintFunctor, SumFunctor, CountFunctor) show how separating traversal logic from per-node actions makes the same traversal reusable for printing, summing, and counting.

📖 Learning Objectives

By completing this activity, you will be able to:

  • Implement insert recursively, understanding that new nodes always become leaves and duplicates are ignored
  • Implement search and explain why it is identical to binary search on a sorted array, achieving O(log n) on a balanced tree
  • Implement in-order traversal and explain why it produces sorted output given the BST property
  • Implement pre-order and post-order traversals and identify a real use case for each (copy/serialize vs. safe deletion)
  • Implement height recursively, using -1 as the base case for nullptr so a leaf has height 0
  • Explain what a functor is and why it is more flexible than a hardcoded print traversal — a struct with operator() can carry state (running sum, count) that a plain function cannot

📝 What You’ll Do

Work through BinarySearchTree.cpp section by section, implementing each method as the instructor explains the concept. Sections 1–5 are TODOs (constructor through height); Section 7 is a provided functor demo with discussion. After each section, run main.cpp to verify output. The session closes with Section 3 of main: three pre-built functors (PrintFunctor, SumFunctor, CountFunctor) applied via inorder_apply to show how the same traversal can print, sum, or count without rewriting traversal logic.

📚 Teaching Order

Work through the files in the order main.cpp calls them:

1. BinarySearchTree.h — Node struct and class declaration

Section What You’ll Learn

2. Functors.h — Functor definitions (provided)

Section What You’ll Learn
PrintFunctor stateless; operator()(int) prints value + space; callable like a function
SumFunctor stateful; accumulates total; persists state between calls via struct member
CountFunctor stateful; increments count regardless of value; ignores the argument entirely

3. BinarySearchTree.cpp — Implementations (6 TODOs + functor discussion)

Section What You’ll Learn
Section 1: Constructor / Destructor initialize root_ to nullptr; destroy_ uses post-order to free children before parent
Section 2: insert / insert_ return-the-node pattern; BST property routes each value left or right; new nodes land as leaves
Section 3: search / search_ identical logic to binary search; each comparison eliminates one subtree; O(log n) on balanced tree
Section 4a: inorder / inorder_ Left-Root-Right; produces ascending sorted output by the BST property
Section 4b: preorder / preorder_ Root-Left-Right; root is first; useful for cloning/serializing the tree
Section 4c: postorder / postorder_ Left-Right-Root; root is last; same order as safe deletion
Section 5: height / height_ base case nullptr = -1; leaf = 0; recursive max + 1
Section 7: Functors (provided, discussion only) no TODO; discuss why inorder_apply is a template, how the compiler generates one version per functor type, and why functors beat function pointers for stateful operations

4. main.cpp — Demo driver (3 sections)

Section What You’ll Learn
Section 1: Build and visualize insert 50, 30, 70, 20, 40, 60, 80; print all three traversals and height
Section 2: Search search for values that exist and values that don't; confirm correct true/false
Section 3: Functors apply PrintFunctor (same output as inorder), SumFunctor (total = 350), CountFunctor (count = 7); compare to hardcoded print and discuss why functors win

🔧 Troubleshooting

CMake does not configure automatically

  1. Make sure you have Desktop development with C++ workload installed in Visual Studio
  2. Go to Project → CMake Settings and ensure the configuration is correct
  3. Try Project → Delete Cache and Reconfigure
  4. Verify that CMakeLists.txt is in the root of your cloned repository

Tests fail to build

  • Google Test is fetched automatically via CMake’s FetchContent — make sure you have an internet connection during the first build
  • Do not modify header files in the include/ folder

Running the Program

  1. In Visual Studio, select ct15-binary-search-trees.exe as the startup item from the dropdown
  2. Press Ctrl+F5 to run without debugging
  3. You should see output from each section as you complete the TODOs
Tip: Look for the // ! DISCUSSION: comments in each file — these explain the “why” behind each concept. The // ? SEE DIAGRAM: comments point you to visual aids in the images/ folder.
